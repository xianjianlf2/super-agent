Super Agent 工具系统设计文档
=============================

一、工具注册机制
每个工具通过 ToolRegistry 统一注册，注册信息包含两类：
- 模型层：description、parameters（决定模型怎么调用）
- 运行时层：isConcurrencySafe、isReadOnly、maxResultChars（决定 Agent Loop 怎么管理）

二、结果截断策略
截断采用 Head/Tail 60/40 分割：保留前 60% 和后 40%，中间用 [省略 N 字符] 标记。
为什么不只保留头部？因为很多时候尾部信息同样关键：
- 日志文件：最新条目在尾部
- 代码文件：函数实现往往在尾部
- 配置文件：最近修改的 section 通常在末尾

三、并发锁机制
基于读写锁实现：
- isConcurrencySafe=true  → 共享锁，多个只读工具可并行
- isConcurrencySafe=false → 独占锁，写操作串行执行
等待队列用 Promise resolve 实现，无轮询开销。

四、工具设计最佳实践
1. 错误要显式返回，不要抛异常（模型无法捕获异常）
2. 参数要用 additionalProperties: false 收紧（防止模型乱传参）
3. 错误信息要对模型友好——模型需要理解为什么失败才能换策略
4. 结果格式要结构化——JSON 比自然语言更容易被模型准确解析
