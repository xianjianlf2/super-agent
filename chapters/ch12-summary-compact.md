# 第 12 章：LLM 摘要压缩

## 本章目标

实现第二层上下文压缩：当 Microcompact 之后上下文仍然过大时，调用 LLM 把早期对话压缩成一条结构化摘要。

## 为什么需要它

Microcompact 只能清理旧工具结果，无法压缩用户意图、关键发现、已完成操作和当前状态。长会话继续增长时，需要把早期对话折叠成可继续执行任务的摘要。

## 压缩 Prompt

本章使用固定模板约束模型输出：

- 用户意图
- 已完成的操作
- 关键发现
- 当前状态
- 需要保留的细节

Prompt 明确要求文件路径、UUID、版本号等标识符原样保留，并限制总长度在 800 字以内。

## 关键设计

- 切分点向前对齐到最近的 `user` 消息，避免保留消息列表以 `assistant` 或 `tool` 开头。
- 摘要作为新的 `user` 消息放在消息列表最前面。
- 已有 `[上下文摘要]` 会参与下一次压缩，实现累积摘要。
- 摘要输出必须包含所有模板字段，否则丢弃结果并保留原始消息。
- 模型调用失败时返回原始消息列表，不能影响 Agent 正常工作。

## 核心实现

- `src/agent/summary-compact.ts`：摘要 Prompt、消息渲染、边界切分、摘要校验和失败降级。
- `src/agent/summary-compact.test.ts`：覆盖边界切分、已有摘要合并、无效摘要跳过和失败保护。

## 运行方式

```bash
pnpm test -- src/agent/summary-compact.test.ts
```

## 常见坑

- 不要让切分点落在 `tool` 消息上，很多 LLM API 要求消息序列以 `user` 开始。
- 不要接受缺少结构化字段的摘要，低质量摘要会让后续对话丢失关键信息。
- 不要把压缩失败当成主流程失败，摘要压缩只是优化，不应该阻断 Agent。
